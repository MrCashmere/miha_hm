## 1. 切换 Tab 后列表不回顶部（✅ 已解决）

> **已修复并在真机上确认可用（1.1.3-OS）。**
>
> **根因：** `HdsTabs` 的 `index` 是**受控属性**，而 `onSelected`（切换动画**开始**时触发）
> 里就改了 `this.activeTab`。官方文档写明「构造的状态变量被动态修改」本身会**再触发一次切换 /
> 布局**——这一下正好把紧随其后的滚动指令冲掉。所以表现一直是「第一次切换无效、再点一次就好了」。
>
> **解法：** 参照同作者的姊妹项目 **CLink**（`github.com/MrCashmere/CLink`，同一套
> `HdsTabs` + 每页独立 `Scroller` + `scrollEdge(Edge.Top)` 架构且工作正常），
> 逐行比对后对齐了**四处差异**，见下方「根因与修复」。

### 现象

在首页点底部/侧边标签栏切换 Tab，再切回来时，列表停在**上次的滚动位置**，而不是回到顶部。

历史反馈的完整症状序列（按时间顺序）：

| # | 反馈 | 说明 |
| --- | --- | --- |
| 1 | 自动回正依旧没有生效 | 初版实现 |
| 2 | 列表是停在上次的位置 | 同上 |
| 3 | 再点击一次其他卡片就能正常回正 | **关键线索**：第二次触发有效，第一次无效 |
| 4 | 切页面不回正，反而正常下滑会回正，而且失去了动画 | 见下方「已排除的原因」 |
| 5 | 切换页面后快速下滑会被回正，但是再切换就完全不会回正了 | 定时重试与用户滑动互相打架 |
| 6 | 切 Tab 还是不回顶部 | 改用 `onChange` 后 |
| 7 | 回正还是失效 | 分帧重试后，仍然失效 |

### 修复后的现状

`entry/src/main/ets/pages/HomePage.ets`：

| 符号 | 作用 |
| --- | --- |
| `onTabChanged(index)` | 唯一入口，绑定 `HdsTabs.onChange`（动画**结束后**触发） |
| `resetPaneScrolls()` | 同步、一次复位全部四个 `Scroller` |

**历史上那套「分帧重试」的机制已全部删除**，不要再捡回来：

| 已删除 | 为什么删 |
| --- | --- |
| `RECENTER_MAX_ATTEMPTS` / `RECENTER_FRAME_MS` / `recenterStep` | 分帧重试是在跟「额外一次布局」抢时序，根因消除后它只是噪音 |
| `recenteredTab` / `recenterToken` / `abortRecenter` | 令牌与中止逻辑是为重试链服务的；同步复位不需要 |
| 四个 pane `Scroll` 上的 `.onTouch` | 只为「中止复位」而挂，多余的手势回调还会干扰滚动手势链 |
| `onSelected` 回调 | 它就是根因：在动画开始时改受控属性 |

### 已经确立的官方事实

来自 SDK 声明（`@hms.hds.hdsBaseComponent.d.ets`，`HdsTabsAttribute`）：

```
onSelected —— "Animation is not necessarily complete"
              切换动画「开始时」触发 / 切换「之前」触发
              （滑动切换时在过渡动画开始时触发，点击切换时在切换前触发）

onChange   —— "triggered after transition animation is completed"
              切换动画「结束后」触发 / 切换「之后」触发
```

来自 `component/scroll.d.ts`：

```
scrollEdge(value: Edge, options?: ScrollEdgeOptions)   // 行 395
currentOffset(): OffsetResult                          // 行 467
  「If the scroller not bound to a component, the return value is void.」
  → Scroller 未绑定组件时返回 void（此时读 .yOffset 会抛错）
  → 未绑定 / 容器未完成布局时，滚动指令被静默丢弃：不生效，也不报错
```

### 已排除的原因

- **不是 `onScrollStart` 误触发**：历史上四个 `Scroll` 都挂了 `.onScrollStart → scheduleScrollToTop()`，
  导致「正常下滑也会回正」。该钩子与全部定时重试代码已删除。
  → 现在只在 `onTouch(TouchType.Down)` 里做**中止**，不再发起复位。
- **不是 `scrollTo({animation: false})` 取消动画**：该写法已删除，改用 `scrollEdge(Edge.Top)`。
- **不是 `onAppear` 每次都触发**：pane 上的 `onAppear → onPaneAppear()` 已删除。
- **不是回调没触发**：`onSelected` 下 `activeTab` 能正常更新（标签栏高亮、标题、页面数据都会跟着变），
  说明回调链路是通的，问题出在**发指令的时机或目标**。

### 顶栏的「列表回正」按钮

首页顶栏那个 `sys.symbol.rectangle_split_2x1` 按钮保留着，走的是同一个
`resetPaneScrolls()`，用于「我就想立刻回顶」的主动操作；**它不再是这个问题的临时手段**。

## 根因与修复（对齐 CLink）

CLink 是同作者的姊妹项目（HarmonyOS 局域网互传），Tab 与滚动架构与本仓库完全一致：
`HdsTabs` + `HdsTabsController` + 每页一个 `Scroller` + 切换时 `scrollEdge(Edge.Top)`。
逐行比对后确认四处差异，已全部对齐：

| # | 本仓库（同步前） | CLink | 为什么这可能是根因 |
| --- | --- | --- | --- |
| **1** | `.onSelected` 与 `.onChange` **都挂**；`onSelected`（动画**开始**时）里就 `this.activeTab = index` | **只挂 `.onChange`**，`onSelected` 出现 **0 次**；`activeTab` 只在动画结束后赋值 | `HdsTabs({ index: this.activeTab })` 是**受控属性**，官方文档写明「构造的状态变量被动态修改」本身会再触发一次切换。在动画中途改它 → 目标页重新布局 → 紧随其后的滚动指令被丢弃。**这是最可能的根因**，也正好命中原文的假设 1 |
| **2** | `Scroll` 同时设 `.height('100%')` **和** `.layoutWeight(1)`（messagesPane / homePane / minePane） | `Scroll` 是 pane 根节点，只有 `.height('100%')` | 两套尺寸来源冲突，可能让滚动容器的测量高度不可靠。infoPane 本来就只有 `layoutWeight`，是唯一没有这个冲突的 pane |
| **3** | `scrollEdge` 放在 `setTimeout(0)` + 令牌 + 4 帧重试链里 | **同步调用**，一次复位**全部四个** Scroller | 若假设 1 成立（存在额外布局），延时一帧反而正好落在重新布局**之后**；同步复位且不区分目标页，才不依赖「哪个 pane 已完成布局」 |
| **4** | `Scroll` 上挂 `.onTouch`（中止复位用） | 没有 | 多余的手势回调可能影响滚动手势链 |

### 同步后的实现

```ts
private onTabChanged(index: number): void {
  FeedbackLogService.recordOperation('UI', `切换标签 ${index}`);
  this.activeTab = index;      // 只在 onChange 里改，且先于复位
  this.resetPaneScrolls();     // 同步、一次复位全部四个
  // ...各页副作用（进消息页拉消息、进信息页刷新等）
}

private resetPaneScrolls(): void {
  const scrollers: Scroller[] = [
    this.homeScroller, this.messageScroller, this.infoScroller, this.mineScroller
  ];
  for (let i = 0; i < scrollers.length; i++) {
    try {
      scrollers[i].scrollEdge(Edge.Top);
    } catch (err) {
    }
  }
}
```

### 需要留意的副作用

**标签栏高亮改为在动画结束后更新。** 高亮由 `this.activeTab === index` 驱动，
而 `activeTab` 现在只在 `onChange` 触发 —— 若「首页平滑切换」开启（300ms 动画），
高亮会滞后约 300ms。CLink 同样是这个行为（它的 `tabItem`/`tabIcon` 也读 `activeTab`，
且未设 `animationDuration`）。

若观感不可接受，两条退路：
1. 关掉「首页平滑切换」→ `animationDuration(0)`，无滞后；
2. 另加一个只驱动标签栏的 `@State`，在 `onSelected` 里更新它而**不动 `activeTab`**
   —— 受控属性不变就不会触发额外切换，根因仍然被消除。
