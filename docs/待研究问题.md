## 1. 切换 Tab 后列表不回顶部（未解决）

### 现象

在首页点底部/侧边标签栏切换 Tab，再切回来时，列表停在**上次的滚动位置**，而不是回到顶部。

历史反馈的完整症状序列（按时间顺序）：

| # | 反馈 | 说明 |
| --- | --- | --- |
| 1 | 自动回正依旧没有生效 | 初版实现 |
| 2 | 列表是停在上次的位置 | 同上 |
| 3 | 再点击一次其他卡片就能正常回正 | **关键线索**：第二次触发有效，第一次无效 |
| 4 | 切页面不回正，反而正常下滑会回正，而且失去了动画 | 见下方「已排除的原因」 |
| 5 | 切换页面后快速下滑会被回正，但是再切换就完全不会回正了 | 定时重试与用户滑动互相打架 |
| 6 | 切 Tab 还是不回顶部 | 改用 `onChange` 后 |
| 7 | 回正还是失效 | 分帧重试后，仍然失效 |

### 当前代码状态

`entry/src/main/ets/pages/HomePage.ets`：

| 符号 | 作用 |
| --- | --- |
| `RECENTER_MAX_ATTEMPTS = 4` / `RECENTER_FRAME_MS = 16` | 分帧重试参数（≈64ms 窗口） |
| `recenteredTab` | 已复位过的 Tab 下标，挡住同下标连续回调 |
| `recenterToken` | 复位令牌，切页或用户触摸时自增，旧的重试链据此退出 |
| `onTabChanged(index)` | 绑定 `HdsTabs.onChange` |
| `scrollCurrentTabToTop(index)` | 发起一次复位，生成新令牌 |
| `recenterStep(target, index, token, attempt)` | 逐帧发 `scrollEdge(Edge.Top)` |
| `abortRecenter()` | 挂在 4 个 pane `Scroll` 的 `.onTouch(TouchType.Down)` 上 |
| `scrollerForTab(index)` | 下标 → `homeScroller` / `messageScroller` / `infoScroller` / `mineScroller` |

四个 `Scroll` 与 Scroller 的绑定位置：`messagesPane` / `homePane` / `infoPane` / `minePane`。
三个切页入口（穿戴 `wearableTabButton`、宽屏 `HdsTabs`、手机 `HdsTabs`）都汇到 `onTabSelected`。

### 已经确立的官方事实

来自 SDK 声明（`@hms.hds.hdsBaseComponent.d.ets`，`HdsTabsAttribute`）：

```
onSelected —— "Animation is not necessarily complete"
              切换动画「开始时」触发 / 切换「之前」触发
              （滑动切换时在过渡动画开始时触发，点击切换时在切换前触发）

onChange   —— "triggered after transition animation is completed"
              切换动画「结束后」触发 / 切换「之后」触发
```

来自 `component/scroll.d.ts`：

```
scrollEdge(value: Edge, options?: ScrollEdgeOptions)   // 行 395
currentOffset(): OffsetResult                          // 行 467
  「If the scroller not bound to a component, the return value is void.」
  → Scroller 未绑定组件时返回 void（此时读 .yOffset 会抛错）
  → 未绑定 / 容器未完成布局时，滚动指令被静默丢弃：不生效，也不报错
```

### 已排除的原因

- **不是 `onScrollStart` 误触发**：历史上四个 `Scroll` 都挂了 `.onScrollStart → scheduleScrollToTop()`，
  导致「正常下滑也会回正」。该钩子与全部定时重试代码已删除。
  → 现在只在 `onTouch(TouchType.Down)` 里做**中止**，不再发起复位。
- **不是 `scrollTo({animation: false})` 取消动画**：该写法已删除，改用 `scrollEdge(Edge.Top)`。
- **不是 `onAppear` 每次都触发**：pane 上的 `onAppear → onPaneAppear()` 已删除。
- **不是回调没触发**：`onSelected` 下 `activeTab` 能正常更新（标签栏高亮、标题、页面数据都会跟着变），
  说明回调链路是通的，问题出在**发指令的时机或目标**。

### 尚未验证的关键假设

按可能性排序，下次直接从第 1 条查：

1. **`HdsTabs` 的 `index` 单向回灌导致重新布局。**
   `HdsTabs({ controller, index: this.activeTab })` 把 `activeTab` 作为受控属性传了进去，
   而 `onSelected` 里又会 `this.activeTab = index`。按 `HdsTabs` 文档，**state 变量的变化本身
   就会触发一次切换/布局**（文档列出的触发条件第 3 条），这一下可能把刚发出去的滚动指令冲掉。
   → 试法：去掉 `index: this.activeTab`，改成不受控（只用 `tabsController.changeIndex()` 做程序化切换），
   让 `activeTab` 只做镜像。注意 `aboutToAppear` 里 `defaultHomeTab === 'info'` 会设 `activeTab = 1`，
   去掉受控属性后要改成 `tabsController.changeIndex(1)`。

2. **`Scroller` 实际没有绑定到当前那个 `Scroll` 节点。**
   如果 `TabContent` 在切换时销毁重建子树，`homeScroller` 可能还指着已经废弃的旧节点，
   `scrollEdge` 自然无效。
   → 试法：在 pane 的 `Scroll.onAppear` 里打一行 `currentOffset()`，
   凡是读到 void / 抛错就说明那一刻没绑上；再看切回来时是否又有 `onAppear`。
   **注意**：`onAppear` 只用来**打日志**，绝不能再挂复位逻辑（历史上就是这么翻车的）。

3. **`scrollEdge` 对嵌套在 `Column` + `layoutWeight(1)` 里的 `Scroll` 无效。**
   `homePane` 的 `Scroll` 同时写了 `.height('100%')` 和 `.layoutWeight(1)`，是互相冲突的两套高度来源。
   → 试法：二选一（在 `Column` 里保留 `layoutWeight(1)`，去掉 `height('100%')`），或换 `scrollTo({yOffset: 0})` 对比。

4. **`HdsTabs` 内部压根没走 `TabContent` 的复用路径**，每次切换都是新建。
   那样列表**本来就该在顶部**——与现象矛盾，但值得用 `onAppear` 日志确认一次。

### 没试过但理论上更稳的替代方案

- **离开时复位（推荐先试这个）。** 在 `onSelected` 里复位**即将离开**的那个 Tab：
  那一刻旧 pane 仍然是激活且已完成布局的，`scrollEdge` 必然生效；等用户切回来时它已经在顶部。
  代价：切换动画期间旧页面内容会瞬移到顶部（它是滑走的，观感损失有限）。
  实现要点：`onSelected(index)` 触发时 `this.activeTab` **还是旧值**，必须在赋值**之前**取。
- **换回原生 `Tabs`。** `HdsTabs` 是 UIDesignKit 的封装，行为不完全透明；
  原生 `Tabs` + `TabContent` + `onChange` 的资料和案例多得多。
- **让 pane 不保留滚动状态。** 给每个 pane 外面套一层会随 `activeTab` 变化的 `if`/key，
  强制切页时重建 `Scroll`。代价是每次切换都重新构建整页，长列表会有明显卡顿，谨慎使用。

### 真机日志怎么读

`recenterStep` 每帧会打一行：

```
Tab 1 第 0 帧复位，偏移 812
Tab 1 第 1 帧复位，偏移 0
```

过滤 `HomePage` 即可。三个值的含义：

| 偏移 | 含义 | 指向 |
| --- | --- | --- |
| `-1` | `Scroller` 没绑上组件（`currentOffset()` 返回 void，读 `.yOffset` 抛错） | 假设 2 |
| `> 0` | 绑上了，但滚动指令被丢弃 | 假设 1 或 3 |
| `0` | 真的到顶了 | 正常 |

**如果一行都没有**，说明 `onTabChanged` 根本没被调用 → 回到 `HdsTabs` 回调本身（假设 4）。

### 临时缓解

首页顶栏有一个「列表回正」按钮（`sys.symbol.rectangle_split_2x1`），
走的是同一个 `scrollCurrentTabToTop(this.activeTab)`，在用户主动点击的场景下是可用的。
